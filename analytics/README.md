# WB Analytics — воронка продаж

Рабочий блок проекта для выгрузки воронки продаж WB.

## Зафиксированная логика

Периоды:

- текущий: последние 7 полных дней до вчера;
- прошлый: предыдущие 7 полных дней.

Основной метод:

`POST /api/analytics/v3/sales-funnel/products`

В итоговой версии планируем одну строку на один артикул WB.

Обязательные показатели:

- переходы в карточку;
- добавления в корзину;
- заказы и сумма заказов;
- выкупы и сумма выкупов;
- отмены и сумма отмен;
- средняя цена;
- конверсия карточка → корзина;
- конверсия корзина → заказ;
- процент выкупа;
- средние заказы в день за текущий период;
- средние заказы в день за прошлый период;
- динамика между периодами.

Для средних заказов в диагностике сохраняются одновременно:

- значение `avgOrdersCountPerDay`, которое возвращает API;
- собственный расчёт `orderCount / 7`.

Это позволит сверить формулу WB на реальных данных кабинета.

## Дни в наличии

Выбран вариант: товар считается в наличии, если остаток был больше нуля хотя бы где-либо:

- на складах WB;
- или на складах продавца/FBS.

То есть для отчёта истории остатков используется режим всех складов (`stockType = ""`).

Источник: Seller Analytics CSV, тип отчёта:

`STOCK_HISTORY_DAILY_CSV`

Планируем считать отдельно:

- Дней в наличии — текущий период;
- Дней в наличии — прошлый период.

День считается днём в наличии, если суммарный остаток товара на 23:59 больше 0.

## Первый диагностический запуск

1. Скопировать `wb_analytics_token.example.txt` в `wb_analytics_token.txt`.
2. Вставить токен категории «Аналитика».
3. Запустить `Запустить_WB_Воронка_Диагностика.cmd`.
4. Скрипт выполняет ровно 1 API-запрос.
5. На выходе:
   - `01_SALES_FUNNEL_RAW.json`
   - `01_SALES_FUNNEL_SAMPLE.csv`

После проверки структуры ответа добавим полный CSV и историю остатков.


## Результат первой диагностики

Первый запрос `/api/analytics/v3/sales-funnel/products` успешно отработал на реальном кабинете.

Подтверждено:

- API возвращает одновременно `selected`, `past` и `comparison`;
- поле `avgOrdersCountPerDay` присутствует и для текущего, и для прошлого периода;
- на 7-дневном окне оно соответствует `orderCount / 7` с округлением WB до 1 знака;
- `comparison.orderCountDynamic` можно использовать как динамику заказов между периодами;
- в ответе есть текущие остатки отдельно `stocks.wb` и `stocks.mp`;
- русские строки в Windows PowerShell 5.1 нужно декодировать из ответа API принудительно как UTF-8 — это исправлено в тестовой ветке.

## Диагностика истории остатков

Добавлен отдельный безопасный тест:

`Запустить_WB_Остатки_История_Диагностика.cmd`

Он:

1. читает первые 20 артикулов из успешного `01_SALES_FUNNEL_RAW.json`;
2. создаёт один отчёт `STOCK_HISTORY_DAILY_CSV`;
3. период — 14 полных дней: текущие 7 + предыдущие 7;
4. `stockType = ""`, то есть WB + склады продавца;
5. ждёт готовность с интервалом 22 секунды;
6. скачивает ZIP и извлекает `02_STOCK_HISTORY_SAMPLE.csv`.

Создание этого теста расходует одну задачу из суточного лимита CSV-отчётов WB.


## Рабочая выгрузка

После проверки реального `STOCK_HISTORY_DAILY_CSV` подтверждена структура истории остатков:

- одна строка на сочетание NmID / тип склада;
- `OfficeName = Свой склад` — FBS;
- `OfficeName = Склад WB` — склад WB;
- даты идут отдельными колонками;
- для расчёта дней в наличии строки по одному NmID суммируются по каждой дате;
- день считается в наличии, если сумма WB + FBS > 0.

Рабочий запуск:

`Запустить_WB_Воронка_7дней.cmd`

Результат:

`WB_Воронка_7дней.csv`

Одна строка = один артикул WB.

Включено:

- показатели текущих 7 полных дней;
- показатели предыдущих 7 дней;
- средние заказы WB за оба периода;
- динамика средних заказов;
- дни в наличии за оба периода;
- дополнительный расчёт заказов на день в наличии;
- конверсии, выкупы, отмены, средняя цена, избранное;
- текущий остаток WB и FBS.

Для истории остатков создаётся ровно один `STOCK_HISTORY_DAILY_CSV` за 14 дней на запуск.


## Зафиксированная рабочая версия

Версия подтверждена ручной проверкой и принята как рабочая.

Основная логика:

- одна строка итогового CSV = один артикул WB;
- текущий период = последние 7 полных дней до вчера;
- прошлый период = предыдущие 7 полных дней;
- средние заказы за оба периода берутся из WB API;
- дни в наличии за оба периода рассчитываются локально по `STOCK_HISTORY_DAILY_CSV`;
- день считается в наличии, если суммарный остаток по складам WB + продавца/FBS больше 0;
- дополнительно рассчитываются заказы на день наличия;
- история остатков запрашивается одним CSV-отчётом на 14 дней;
- если подходящий локальный CSV истории уже скачан, он повторно используется без создания нового отчёта WB;
- итоговый CSV записывается с разделителем `;` в Windows-1251 для стабильной работы Excel/Power Query.

Рабочий файл:

`WB_Воронка_7дней.csv`

Power Query должен читать его с явными параметрами:

- Delimiter = `;`
- Encoding = `1251`
