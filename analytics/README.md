# WB Analytics — воронка продаж

Тестовая ветка для следующего блока проекта.

## Зафиксированная логика

Периоды:

- текущий: последние 7 полных дней до вчера;
- прошлый: предыдущие 7 полных дней.

Основной метод:

`POST /api/analytics/v3/sales-funnel/products`

В итоговой версии планируем одну строку на один артикул WB.

Обязательные показатели:

- переходы в карточку;
- добавления в корзину;
- заказы и сумма заказов;
- выкупы и сумма выкупов;
- отмены и сумма отмен;
- средняя цена;
- конверсия карточка → корзина;
- конверсия корзина → заказ;
- процент выкупа;
- средние заказы в день за текущий период;
- средние заказы в день за прошлый период;
- динамика между периодами.

Для средних заказов в диагностике сохраняются одновременно:

- значение `avgOrdersCountPerDay`, которое возвращает API;
- собственный расчёт `orderCount / 7`.

Это позволит сверить формулу WB на реальных данных кабинета.

## Дни в наличии

Выбран вариант: товар считается в наличии, если остаток был больше нуля хотя бы где-либо:

- на складах WB;
- или на складах продавца/FBS.

То есть для отчёта истории остатков используется режим всех складов (`stockType = ""`).

Источник: Seller Analytics CSV, тип отчёта:

`STOCK_HISTORY_DAILY_CSV`

Планируем считать отдельно:

- Дней в наличии — текущий период;
- Дней в наличии — прошлый период.

День считается днём в наличии, если суммарный остаток товара на 23:59 больше 0.

## Первый диагностический запуск

1. Скопировать `wb_analytics_token.example.txt` в `wb_analytics_token.txt`.
2. Вставить токен категории «Аналитика».
3. Запустить `Запустить_WB_Воронка_Диагностика.cmd`.
4. Скрипт выполняет ровно 1 API-запрос.
5. На выходе:
   - `01_SALES_FUNNEL_RAW.json`
   - `01_SALES_FUNNEL_SAMPLE.csv`

После проверки структуры ответа добавим полный CSV и историю остатков.
