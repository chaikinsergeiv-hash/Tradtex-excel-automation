# WB Advertising

Эта папка содержит только подтвержденные рабочие инструменты для рекламного API Wildberries.

## Файлы

- `WB_Ads_API_Raw_Dump.ps1` — рабочая выгрузка структуры рекламного API в RAW JSON и удобные CSV-файлы для анализа.
- `Запустить_WB_Реклама_RAW.cmd` — запуск RAW-выгрузки.
- `WB_Ads_RateLimit_Diagnostic.ps1` — диагностика токена и лимитов рекламного API.
- `Запустить_Диагностику_WB_Реклама.cmd` — запуск диагностики.
- `WB_Ads_7days.ps1` — статистика рекламы за последние 7 полных дней. История затрат загружается по одному дню, чтобы снизить риск таймаута `/adv/v1/upd`.
- `Запустить_WB_Реклама_7дней.cmd` — запуск 7-дневной статистики.
- `wb_adv_token.example.txt` — пример файла токена.

## Токен

Создай рядом локальный файл:

`wb_adv_token.txt`

и вставь в него персональный токен Wildberries категории **Продвижение**.

Настоящий токен не хранится в GitHub и исключен через `.gitignore`.

## Рекомендуемый порядок проверки на новом устройстве

1. Создать `wb_adv_token.txt`.
2. Запустить `Запустить_Диагностику_WB_Реклама.cmd`.
3. Убедиться, что ответ API — `HTTP 200 OK`.
4. Запустить `Запустить_WB_Реклама_RAW.cmd`.
5. Проверить появление файлов:
   - `01_UPD_RAW.json`
   - `01_UPD_FLAT.csv`
   - `02_ADVERTS_RAW.json`
   - `02_ADVERTS_TOP.csv`
   - `03_FULLSTATS_SAMPLE_RAW.json`
   - `03_FULLSTATS_SAMPLE_FLAT.csv`
6. Для проверки 7-дневной статистики запустить `Запустить_WB_Реклама_7дней.cmd`.
7. Проверить появление `WB_Реклама_7дней.csv`.

## VPN и доступ к WB API

Если запросы к `advert-api.wildberries.ru` зависают, завершаются timeout или ошибкой вида:

`The underlying connection was closed: An unexpected error occurred on a send.`

проверь VPN и сетевой маршрут до Wildberries.

На практике рекламный API может быть недоступен через некоторые VPN/зарубежные маршруты, даже если обычный интернет работает. В таком случае:

1. отключи VPN или переключись на маршрут, с которого доступен Wildberries;
2. проверь соединение командой:
   `curl.exe -v --connect-timeout 10 --max-time 20 https://advert-api.wildberries.ru/ -o NUL`;
3. только после успешного соединения запускай рекламные скрипты.

Для ежедневного запуска через Планировщик Windows сеть/VPN должны быть в рабочем состоянии к моменту старта задачи.


## Тест: все кампании с расходом

В ветке `test-advertising-all-spend` 7-дневный отчёт работает в тестовом режиме:

- берёт все кампании с фактическим расходом > 0 ₽;
- не использует прежний порог 100 ₽;
- добавляет колонку `Принятые заказы` = `Заказы (acc.) - Отмены заказов`;
- пишет результат в отдельный файл `WB_Реклама_7дней_TEST.csv`, поэтому рабочий CSV не перезаписывается;
- перед `fullstats` считает число пакетов;
- если потребуется больше 6 пакетов по 50 кампаний, скрипт остановится до первого запроса `fullstats`.

При текущем объёме около 280 кампаний ожидается 6 пакетов — столько же, сколько было в проверенной версии с фильтром 100 ₽.

## Логика тестового отчёта: одна строка = одна РК

В ветке `test-advertising-all-spend` отчёт перестроен вокруг рекламной кампании, а не вокруг каждого `nmId` из `fullstats`.

Правило проекта:

- нормальная РК содержит один рекламируемый артикул;
- этот артикул определяется только по `nm_settings` самой кампании;
- все показатели `fullstats`, включая ассоциативные конверсии по другим товарам, суммируются в общие показатели этой РК;
- чужие `nmId` из ассоциативных конверсий не создают отдельные строки в основном отчёте.

Основной файл:

`WB_Реклама_7дней_TEST.csv`

Структура: одна строка = одна рекламная кампания.

В тестовой версии также оставлены контрольные поля:

- `Ассоц. заказы (контроль)`;
- `Ассоц. отмены (контроль)`;
- `Ассоц. выручка (контроль)`.

Они уже входят в общие показатели кампании и нужны только для сверки с интерфейсом WB.

### Кампании с несколькими артикулами

Если в `nm_settings` одной РК найдено больше одного артикула, в основном CSV:

- поле `Артикул` остаётся пустым;
- поле `Артикулы РК` содержит список всех найденных артикулов;
- `Проверка РК` = `ВНИМАНИЕ: несколько артикулов`.

Дополнительно создаётся файл:

`WB_Реклама_МУЛЬТИАРТИКУЛ_TEST.csv`

Это список кампаний, которые нарушают наше правило «1 РК = 1 артикул» и которые нужно будет разобрать/заменить.
