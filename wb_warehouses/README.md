# WB — остатки по складам Wildberries

Отдельный блок проекта для выгрузки текущих остатков по конкретным складам WB.

## Принцип

Этот блок независим от:

- `stocks/` — FBS остатки продавца;
- `advertising/` — реклама;
- `analytics/` — воронка продаж.

Работа ведётся в отдельной папке, чтобы изменения не затрагивали уже утверждённые рабочие блоки.

## Токен

Используется токен WB API категории «Аналитика».

Для локального запуска создать рядом со скриптом:

`wb_analytics_token.txt`

В GitHub хранится только шаблон без реального токена.

## Планируемый результат

Одна строка = один артикул WB.

Колонки:

- Артикул WB
- Артикул продавца
- Наименование
- отдельная колонка на каждый склад WB
- Итого WB

Если один артикул имеет несколько размеров/ChrtID, остатки по ним суммируются внутри артикула по каждому складу.

## Этап разработки

Сначала делаем диагностический запрос и смотрим реальную структуру ответа кабинета. После проверки фиксируем состав CSV и рабочий скрипт.


## Диагностика API

Добавлен безопасный тест:

`Запустить_WB_Склады_Диагностика.cmd`

Перед запуском:

1. скопировать `wb_analytics_token.example.txt` в `wb_analytics_token.txt`;
2. вставить токен категории «Аналитика»;
3. запустить CMD.

Диагностика делает ровно один запрос:

`POST /api/analytics/v1/stocks-report/wb-warehouses`

с параметрами:

- `limit = 1000`;
- `offset = 0`;
- без фильтра по артикулам — первые 1000 строк кабинета.

Результаты:

- `01_WB_WAREHOUSES_RAW.json` — сырой ответ;
- `01_WB_WAREHOUSES_SAMPLE.csv` — тестовый CSV.

После проверки этих файлов будет собрана финальная агрегация:
один артикул WB × отдельные колонки складов × итоговый остаток WB.

Метод обновляет данные примерно раз в 30 минут и поддерживает offset-пагинацию до 250000 строк за запрос.


## Результат диагностики 05.10.2026

Диагностический запрос успешно выполнен на реальном кабинете.

Получено 675 строк. Во всём ответе присутствует только агрегированный склад WB:

- `warehouseId = -999999`;
- `warehouseName = "Склад WB"`;
- `regionName = "Склад WB"`.

Поля строки:

- `nmId`;
- `chrtId`;
- `warehouseId`;
- `warehouseName`;
- `regionName`;
- `quantity`;
- `inWayToClient`;
- `inWayFromClient`.

То есть текущий ответ API не содержит детализацию по физическим складам (Коледино, Электросталь, Казань и т.д.).

Причина — временное ограничение WB API, действующее с 15.08.2026: в отчётах Analytics and Data с детализацией по складам WB данные по складам WB возвращаются только итогами по размерам товара.

Это не ошибка токена и не ошибка диагностического скрипта.

До восстановления детализации финальный скрипт можно сделать динамическим:
- сейчас он будет формировать агрегированный остаток WB;
- после возврата детализации WB те же данные автоматически развернутся в отдельные колонки по `warehouseName` без изменения архитектуры.


## Рабочая выгрузка

Добавлен рабочий тест:

`Запустить_WB_Остатки_Склады.cmd`

Он:

- получает все страницы `/api/analytics/v1/stocks-report/wb-warehouses`;
- соблюдает паузу 22 секунды между страницами;
- суммирует все `chrtId` одного `nmId`;
- динамически создаёт отдельную колонку для каждого `warehouseName`;
- добавляет `Итого WB`;
- отдельно суммирует `В пути к клиенту` и `В пути от клиента`;
- добавляет контрольное поле `Количество размеров`.

Текущий результат при действующем ограничении WB будет выглядеть так:

- Артикул WB
- Склад WB
- Итого WB
- В пути к клиенту
- В пути от клиента
- Количество размеров

Если WB вернёт детализацию по физическим складам, дополнительные колонки появятся автоматически без изменения логики.

Рабочий итоговый файл:

`WB_Остатки_Склады_WB.csv`

Формат:

- разделитель `;`;
- кодировка Windows-1251;
- одна строка = один артикул WB.


## Зафиксированная рабочая версия

Версия подтверждена и принята как рабочая.

Основная логика:

- одна строка итогового CSV = один артикул WB;
- все chrtId/размеры одного nmId суммируются;
- текущий ответ WB может возвращать агрегированный склад `Склад WB`;
- колонки складов создаются динамически по `warehouseName`;
- при возврате детализации WB новые склады автоматически появятся отдельными колонками;
- `Итого WB` = сумма остатков по всем warehouseName;
- отдельно суммируются `В пути к клиенту` и `В пути от клиента`;
- между страницами API выдерживается пауза 22 секунды;
- CSV записывается с разделителем `;` в Windows-1251.

Рабочий файл:

`WB_Остатки_Склады_WB.csv`
